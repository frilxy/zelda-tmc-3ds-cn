# Embedded fonts

The bottom screen renders Chinese from `port/port_second_screen_cn_font.h`, which
is generated by `scripts/dev/gen_cn_font.py`. Two faces are baked, matching the
Zelda 3 (ALttP) 3DS Chinese port's bottom screen:

| Face | Font | Size | Role |
|---|---|---|---|
| `body` | Fusion Pixel 12px (`port/cn_fonts/fusion-pixel-12px-monospaced-zh_hans.bitmap.ttf`) | 12px | menu text, values, hints |
| `large` | GNU Unifont 18.0.01 (`port/cn_fonts/unifont-18.0.01.otf`) | 16px, synthesized bold | tab labels |

Both are stored as 16x16 2bpp cells (0 = transparent, 1 = outline, 2 = body),
64 bytes per glyph. The outline is baked into the bitmap, so nothing is dilated
at runtime.

## Why the fonts are checked in

The generator needs the source TTFs, and the build has no network access to font
releases. Both originals live in `port/cn_fonts/`.

## Regenerating

```bash
pip install Pillow
python3 scripts/dev/gen_cn_font.py          # rewrite the header
python3 scripts/dev/gen_cn_font.py --check  # verify it is current
```

The character set is discovered by scanning the bottom-screen sources for
printable ASCII plus CJK codepoints, so adding a Chinese string only needs a
re-run. This replaced a hand-maintained table that had silently dropped
`更`, which made `更新` render as `新`.

## History

- Through v2.2.1 the header was a hand-frozen VonwaonBitmap 12px table with a
  per-glyph `uint32_t` mask (576 bytes/glyph). It was replaced because it had no
  generation step, so every new UI string risked a blank glyph.
